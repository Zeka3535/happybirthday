# Папка `assets/`

Сюда складываются все файлы, которые показывает сам квест. Сейчас папка пустая —
сайт работает без единой картинки, поэтому грузится мгновенно.

## Что можно положить

| Файл | Куда подключается | Советы |
|------|-------------------|--------|
| Фото для подсказок | `js/config.js` → `reward.image` | JPEG/WebP, ширина 800–1200 px, до ~200 КБ |
| Картинки для «Памяти» | `js/config.js` → `levels[].pairs[].image` | Квадратные, 300×300 px, до ~50 КБ |
| Музыка | пока не подключена | MP3, 96–128 kbps, до 2 МБ |
| QR-код | `reward.image` или отдельный блок | PNG, чёткий, с полями вокруг |

## Как подключить фото

1. Скопируйте файл в эту папку, например `assets/photo-1.jpg`.
2. Откройте `js/config.js`.
3. В нужном уровне найдите `image: null` и замените на:

```js
image: "assets/photo-1.jpg"
```

Путь указывается относительно `index.html`, без ведущего слэша — так сайт
работает и в корне домена, и в подпапке на GitHub Pages.

## Про «Память» с фото

В главе 3 вместо эмодзи можно показать картинки. В `pairs` у пары есть поля
`emoji` и `image` — если указан `image`, он важнее эмодзи:

```js
{ id: "moon", emoji: "🌙", label: "Луна", image: "assets/mem-moon.jpg" }
```

## Чего лучше избегать

- Огромных фото прямо с телефона (5–10 МБ) — квест будет грузиться долго.
- Имён файлов с пробелами и кириллицей: `assets/фото 1.jpg` может сломаться
  при публикации. Используйте латиницу и дефисы: `assets/photo-1.jpg`.
- Вертикальных видео: они тяжёлые, и на мобильном интернете квест станет
  неприятно медленным.

## Проверка перед публикацией

- [ ] Все файлы из `js/config.js` реально лежат в `assets/`
- [ ] Имена совпадают по регистру (`Photo.JPG` ≠ `photo.jpg` на сервере)
- [ ] Картинки открываются в браузере по прямому адресу
- [ ] Общий вес папки — разумный (лучше до 5 МБ)
